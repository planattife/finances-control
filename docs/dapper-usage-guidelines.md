# Dapper Usage Guidelines

## AI Context (for Copilot / Agents)

You are a **senior .NET software engineer** working on a **financial control system**.

Your task is to:

* Implement **PostgreSQL queries and commands**
* Use **Dapper** for data access
* Follow **clean architecture principles**
* Ensure **code readability, maintainability, and security**

All implementations must follow the standards defined in this document.

## Overview

This document defines the standards for using **Dapper** in this project.
The goal is to ensure:

* Readable repositories

## Connection Factory

Create a shared connection factory inside the `Data` folder so it can be reused across all modules.

```csharp
public class AppDbConnectionFactory
{
    private readonly IConfiguration _configuration;

    public AppDbConnectionFactory(IConfiguration configuration)
    {
        _configuration = configuration;
    }

    public IDbConnection CreateConnection()
        => new SqlConnection(_configuration.GetConnectionString("DefaultConnection"));
}
```

## Repository Guidelines

### 1. Use Dapper for all data access

* Replace any ORM or manual SQL execution with Dapper
* Use as necessary:

  * `QueryAsync<T>`
  * `QueryFirstOrDefaultAsync<T>`
  * `ExecuteAsync`
  * `ExecuteScalarAsync<T>`

---

### 2. Do NOT generate IDs in code

* Remove any:

  * Mock ID generation
  * Auto-increment logic in code
* IDs must be generated by **PostgreSQL**

---

### 3. Always use parameters (SQL Injection protection)

❌ Wrong:

```csharp
var sql = $"SELECT * FROM Product WHERE Id = {id}";
```

✅ Correct:

```csharp
var sql = "SELECT * FROM Product WHERE Id = @Id";
var parameters = new DynamicParameters();
parameters.Add("@Id", id);
```

---

## SQL Organization (IMPORTANT)

### Rule: Keep repositories clean

* DO NOT write SQL directly inside repositories
* Move SQL into separate classes

## Command Pattern Example

Used for INSERT, UPDATE, DELETE

```csharp
public class CreateProductCommand
{
    public (string Sql, DynamicParameters Params) Build(Product product)
    {
        var sql = @"
            INSERT INTO Product (Name, Price)
            VALUES (@Name, @Price);
            RETURNING Id;
        ";

        var parameters = new DynamicParameters();
        parameters.Add("@Name", product.Name);
        parameters.Add("@Price", product.Price);

        return (sql, parameters);
    }
}
```

---

## Query Pattern Example

### Query with parameters

```csharp
public class GetProductByIdQuery
{
    public (string Sql, DynamicParameters Params) Build(int id)
    {
        var sql = @"
            SELECT Id, Name, Price
            FROM Product
            WHERE Id = @Id
        ";

        var parameters = new DynamicParameters();
        parameters.Add("@Id", id);

        return (sql, parameters);
    }
}
```

---

### Query without parameters

```csharp
public class GetAllProductsQuery
{
    public string Sql => @"
        SELECT Id, Name, Price
        FROM Product
    ";
}
```

## Key Principles

* Keep repositories **clean and short**
* Keep SQL **isolated and reusable**
* Always use **parameterized queries**
* Follow **consistent naming**
* Let the **database handle IDs**
* Validate table structure using `Database/Tables`
